## 证据与边界

停车被动采集12秒：ID2前左速度查询240次、回复123次，最大间隔约0.60秒；其他轮回复与查询基本一致。调参线用户确认早已断开。软件原始CAN记录已复现问题，不只是ROS解析。集中查询紧邻同ID控制报文，可能导致报文碰撞；接线、节点配置或驱动器也仍可能有影响，根因尚未证明。

本候选仅验证查询时序假设：在运动任务的四个10ms槽分别查询FL/FR/RL/RR，50ms控制槽不查询，每轮仍20Hz。移除Control_Update内集中四路查询。轮径0.21m、减速比4.43、极对数10不变；150ms反馈有效期、CAN自动重发设置、邮箱5ms中止规则、控制帧与安全门均不改变。不发0xAA、不提高导航速度。

生产函数时序回放旧版失败、新版通过；canonical ./tools/build_blade_ok.sh 完成，主机harness与双板构建通过。编译警告对照见warning-comparison.json。这不证明硬件通信已修复。此前21cm发布和所有失败记录保留。

## 手工刷写

候选未自动刷写、未实车验收。先保持四轮稳定架空，割刀/升降/草袋动力隔离，CH5停止锁定，现场可独立断电；关闭RK3588控制程序。现有PD1软件急停关闭状态继承，不当作可用急停。

在本目录：

```bash
sha256sum -c SHA256SUMS
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg \
  -c 'program control_chassis.elf verify reset exit'
```

只有verify/reset成功才记录刷写成功。不要刷遥控器。需要回退时使用原20261012-wheel-210mm-candidate包，保留诊断失败证据。

## 刷后第一步：静止、锁定、只接收

刷好后回复“诊断固件已刷好”。保持CH5锁定，**不要解锁或转轮**。恢复CAN500kbps后先被动接收12秒，保存原始CAN查询/回复并核对：

|检查|预期|状态|
|---|---|---|
|启动停车|API0，近零轮速，无0x005发布者|未执行|
|查询时序|四轮各约20Hz，查询错开，不与控制槽集中发送|未执行|
|前左回复|查询/回复基本对应，连续间隔不超150ms|未执行|
|另外三轮|回复频率和连续性不退化|未执行|
|CAN健康|保存总线错误计数与日志|未执行|

若只读检查仍失败，不延长有效期、不自动转轮；继续核对CAN ID是否唯一、前左支路连接、驱动器参数与诊断。只有只读检查通过后，才准备新授权架空短测；随后仍需重验停车与圈数。当前不批准地面导航或宣称定位/轮速标定完成。
