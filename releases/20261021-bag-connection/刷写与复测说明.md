# 草袋连接显示：两端刷写与复测

本包的软件验证已完成；以下硬件项目全部待测。不要把主机预览或 GPIO 替身测试当作实机反馈。

## 刷写

| 设备 | 文件 | 写入地址 |
|---|---|---|
| STM32F407 底盘 | `control-chassis-bag-connection.elf` | ELF 自带 |
| FS-i6X 遥控器 | `fs-i6x-bag-connection.bin` | `0x08000000` |

刷写前：保存设备当前底盘/遥控器镜像与遥控器模型，保持原模型、通道映射、反向、端点和校准数据。割刀与草袋电机动力先断开，车轮架空，底盘保持急停或上锁；CH4 回中。不要用全片擦除，不要把遥控器镜像写入底盘。

底盘接 ST-Link，在本目录执行：

```bash
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg \
  -c 'program control-chassis-bag-connection.elf verify reset exit'
```

必须看到 `Verified OK`。

遥控器先进入 USB DFU，用 `dfu-util -l` 确认只连了目标遥控器、Internal Flash 是 alt 0（不是就换成实际值），在本目录执行：

```bash
dfu-util -a 0 -s 0x08000000:leave -D fs-i6x-bag-connection.bin
```

必须看到 `File downloaded successfully`。

没有设备或目标不明时不要烧录。保留模型与 EEPROM，正常开机完成原有安全检查。

BIN／HEX 写法、备份、读回和排障见[通用刷写指南](../../docs/flashing.md)。

## 硬件验收记录

填写时间、操作人、接收机型号、CH6 两端实际值。先在动力隔离/上锁状态验证显示。

| 场景 | 预期及记录内容 | 结果 |
|---|---|---|
| SENS 地址发现 | 确认接收机发现 11，类型 0xE3、两字节，地址 1～10 正常；记录轮询周期 | 待测 |
| 开机无草袋 | 收到推进的有效反馈后显示“草袋未连接”；未收反馈期间显示“草袋未知” | 待测 |
| 无草袋拨 CH6 | 两端及中间值反复拨动，始终“草袋未连接” | 待测 |
| 插入草袋 | PD10 变低；经过正常回传/心跳确认后显示 CH6 对应的“草袋开/关”；记录延迟 | 待测 |
| 已连接拨 CH6 | 约 1000 为开、约 2000 为关；中间/无效显示“草袋--” | 待测 |
| 上锁/急停 | 插拔仍可显示连接变化，显示目标不表示草袋有执行许可 | 待测 |
| 运行中拔出 | 收到断开反馈后显示未连接；现有控制联锁中止输出，分别记录显示与 PWM 时延 | 待测 |
| 重接保持原档 | 显示恢复目标，机构仍按原规则建基线、不自行启动；新拨动才申请动作 | 待测 |
| RF/SENS 断流 | 没有有效心跳推进满 1 秒后，下一次界面刷新显示“草袋未知”；记录实际延迟 | 待测 |
| 恢复与重绑定 | 旧状态不直接复活，收到新心跳推进后恢复 | 待测 |
| 旧底盘兼容 | 没有新地址反馈时显示未知，不误报未连接或开/关 | 待测 |
| 界面 | 五种文字完整，调试页可分别查看草袋连接/指令和全部故障行 | 待测 |
| 既有功能 | CH4/OK 刀盘确认、取消、CH6 不确认刀盘、CH9 高度设定、CH10 调速及安全恢复正常 | 待测 |

“草袋开/关”仍是 CH6 目标。没有物理限位反馈，不能据此宣告机构到位或完成；草袋自身的既有定时动作限制继续适用。

## 回退

优先使用刷写前从设备保存的镜像。包内 `rollback/` 提供之前发布包的候选镜像副本：底盘 `control-chassis-grass-bag-ch6.elf` 与遥控器 `fs-i6x-simple-ui.bin`，可按同样的目标识别和校验步骤恢复。它们没有从当前设备读取，也不保证对应设备原来的固件版本。

回退后不再提供本次草袋连接显示。只回退底盘时，新遥控器显示草袋未知；只回退遥控器时，恢复旧指令页面。
