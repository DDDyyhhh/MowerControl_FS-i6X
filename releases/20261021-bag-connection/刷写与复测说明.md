# 草袋连接显示：两端刷写与复测

本包的软件验证已完成；以下硬件项目全部待测。不要把主机预览或 GPIO 替身测试当作实机反馈。

## 刷写前

1. 保存设备当前底盘/遥控器镜像与遥控器模型。保持原模型、通道映射、反向、端点和校准数据。
2. 沿用已有动力隔离操作：割刀与草袋电机动力先断开，车轮架空，底盘保持急停或上锁；CH4 回中。
3. 在本包目录执行 `shasum -a 256 -c SHA256SUMS`，全部应为 OK。

## 底盘

确认 ST-Link 接在目标 STM32F407 板的 SWDIO、SWCLK、GND，目标电压正常。下面命令会实际烧录、校验并复位：

```bash
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg \
  -c 'program control-chassis-bag-connection.elf verify reset exit'
```

ELF 自带地址。不要用全片擦除或把遥控器镜像写入底盘；保留 OpenOCD 校验日志。

## FS-i6X 遥控器

1. 按原方法进入 STM32 DFU 模式并连接 USB，先执行 `dfu-util -l`。
2. 确认列表中的设备是目标 FS-i6X，并确认 Internal Flash 对应 alt。没有设备或目标不明时不要烧录。
3. 仅在已确认 Internal Flash 的 alt 为 0 时，执行：

```bash
dfu-util -a 0 -s 0x08000000:leave -D fs-i6x-bag-connection.bin
```

若实际 alt 不是 0，使用已确认的值。保留模型与 EEPROM，正常开机完成原有安全检查。

## 硬件验收记录

填写时间、操作人、两端固件 SHA256、接收机型号、CH6 两端实际值。先在动力隔离/上锁状态验证显示。

| 场景 | 预期及记录内容 | 结果 |
|---|---|---|
| SENS 地址发现 | 确认接收机发现 11，类型 0xE3、两字节，地址 1～10 正常；记录轮询周期 | 待测 |
| 开机无草袋 | 收到推进的有效反馈后显示“草袋未连接”；未收反馈期间显示“草袋未知” | 待测 |
| 无草袋拨 CH6 | 两端及中间值反复拨动，始终“草袋未连接” | 待测 |
| 插入草袋 | PD10 变低；经过正常回传/心跳确认后显示 CH6 对应的“草袋开/关”；记录延迟 | 待测 |

“草袋开/关”仍是 CH6 目标。没有物理限位反馈，不能据此宣告机构到位或完成；草袋自身的既有定时动作限制继续适用。

## 回退

优先使用刷写前从设备保存的镜像。包内 `rollback/` 提供之前发布包的候选镜像副本：底盘 `control-chassis-grass-bag-ch6.elf` 与遥控器 `fs-i6x-simple-ui.bin`，可按同样的目标识别和校验步骤恢复。它们没有从当前设备读取，也不保证对应设备原来的固件版本。

回退后不再提供本次草袋连接显示。只回退底盘时，新遥控器显示草袋未知；只回退遥控器时，恢复旧指令页面。
