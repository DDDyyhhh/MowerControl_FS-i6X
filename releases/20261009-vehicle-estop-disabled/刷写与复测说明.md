# 2026-10-09 临时停用车载急停 PD1

用户报告上一版 20261009-tilt-block-commented 已烧录成功且测试通过。本新版尚未烧录、尚未实机验收；不继承上一版的实测结论。

## 修改与恢复

app_Motion.c 内 `VEHICLE_ESTOP_ENABLED=0` 临时停用 PD1 软件输入。主循环急停锁存、集草袋许可、遥控安全门均调用统一函数 VehicleEmergencyActive()，停用时返回 false，不读取 PD1。原主循环急停段已被用户注释，本次恢复为受开关控制的代码，便于后续重新启用。

碰撞锁存、遥控运行许可、断链保护、倾角相关门控保持原样。按钮若接有独立硬件断电回路，该回路不受固件控制。

恢复方式：将 app_Motion.c 中 `#define VEHICLE_ESTOP_ENABLED 0` 改为 `1`，重新执行 `./tools/build_blade_ok.sh` 并烧录；恢复后的软件判断为 PD1 高电平触发，需核对实际按钮常闭/常开接线并实测锁存停车。

## 刷写

| 设备 | 文件 | 写入地址 |
|---|---|---|
| STM32F407 底盘 | `control_chassis.elf` | ELF 自带 |

刷写前：断开割刀动力，车轮架空，底盘供电稳定。仅需烧录底盘板。

底盘接 ST-Link，在本目录执行：

```bash
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg \
  -c 'program control_chassis.elf verify reset exit'
```

必须看到 `Verified OK`。

BIN／HEX 写法、备份、读回和排障见[通用刷写指南](../../docs/flashing.md)。
