# 2026-10-10 API 行走授权修正候选

本包仅用于底层 STM32 控制板。尚未刷写，尚未通过实车转轮验收。遥控器不需要刷写。

## 问题与修正

当前发布版两次架空前进测试均完成 API 1→2 接管、0.1 m/s 命令回显，但四轮实际速度反馈始终为零。源码中 RefreshSafetyOwnershipGate 始终选择遥控控制身份，而 API 行走调用要求 API 身份，真实生产函数的主机回归测试复现授权失败。

候选按实际模式选择控制身份：手动模式保持遥控身份，API 待机不授权非零行走，API 运行要求新鲜 CAN 命令和遥控运行许可。保留物理/软件/遥控锁存、遥控连接/稳定性检查、500 ms API 新鲜度和控制身份切换时的新命令要求。不发送 0xAA，不自动清锁。

此版本继承当前发布版 VEHICLE_ESTOP_ENABLED=0：PD1 软件急停仍关闭。遥控停止和独立断电必须保持有效。候选修正授权问题，不代表电机、轮速反馈或停车功能已经实测通过。

## 构建证据

执行 ./tools/build_blade_ok.sh 成功，全部主机回归及底盘 Debug、mower-ok-release 构建通过。新增测试直接提取生产授权函数，修正前失败、修正后通过；覆盖待机、身份切换、超时、计时回绕、遥控停止和安全锁存。日志见 build.log 与 host_api_ownership.log。保留原有未使用变量等编译警告。

底盘 text=82244、data=452、bss=52628 字节。独立快照和对上一版的差异见 app_Motion.c.snapshot、api-ownership.patch。所有交付文件哈希见 SHA256SUMS。

## 刷写步骤

1. 保持四轮稳定架空，割刀、升降、草袋动力隔离，现场有人能够遥控停止和独立断电。底盘供电稳定。
2. 在本目录执行 sha256sum -c SHA256SUMS。
3. 用 STM32CubeProgrammer / ST-Link 通过 SWD 下载 control_chassis.hex 并校验；仅刷底盘。若使用 BIN，起始地址为 0x08000000。
4. Linux OpenOCD 可在本目录执行：

```bash
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg \
  -c 'program control_chassis.elf verify reset exit'
```

需要操作者批准刷写后才能执行上述烧录命令。编译成功不代表已经烧录。原发布版保留于 ../20261009-vehicle-estop-disabled/，需回退时按相同方法刷写原版本并复测。
