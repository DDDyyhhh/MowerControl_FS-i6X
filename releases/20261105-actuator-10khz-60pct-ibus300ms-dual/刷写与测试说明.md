# 恢复两路推杆10kHz／60%：双端刷写与测试说明

本轮软件验证和双端构建已通过，尚未实际刷写。底盘BIN与原10kHz／60%已验证镜像逐字节一致；本次按用户要求恢复该配置，声音改善仍需现场短程复测。以下命令在解压后的发布包目录执行。10kHz及60%改动位于底盘，原配套协议0x36遥控器可以继续使用；需要完整双端部署时使用本包两端文件。

## 刷写

| 设备 | 文件 | 写入地址 |
|---|---|---|
| STM32F407 底盘 | `control-chassis-actuator-10khz-60pct-ibus300ms.bin` | `0x08000000` |
| FS-i6X 遥控器 | `fs-i6x-actuator10khz60pct-paired.bin` | `0x08000000` |

刷写前：固定设备，断开行走、割刀和推杆电机动力，仅保留控制板、接收机逻辑供电。接收机保留已整改的数字地接法。保留MODEL01、校准、绑定、通道及CH5失控配置，不恢复出厂、不初始化外部EEPROM、不改Option Bytes。

底盘接 ST-Link，在本目录执行：

```bash
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg \
  -c 'adapter speed 100' -c 'reset_config none' \
  -c 'program control-chassis-actuator-10khz-60pct-ibus300ms.bin 0x08000000 verify reset exit'
```

必须看到 `Verified OK`。

遥控器先进入 USB DFU，用 `dfu-util -l` 确认只连了目标遥控器、Internal Flash 是 alt 0（不是就换成实际值），在本目录执行：

```bash
dfu-util -a 0 -s 0x08000000 -D fs-i6x-actuator10khz60pct-paired.bin
```

必须看到 `File downloaded successfully`。完成后拔 USB，正常开机。

两端均附有同名HEX、ELF和MAP；HEX包含地址，ELF/MAP与各自BIN配套，不混用旧版符号。TIM2/TIM3由84MHz计数，PSC=0、ARR=8399；10kHz周期约100µs，60%比较值5040。没有NRST接线时，沿用不依赖NRST的连接方式。

BIN／HEX 写法、备份、读回和排障见[通用刷写指南](../../docs/flashing.md)。

## 刷后检查及运行边界

1. 保留原MODEL01、校准、绑定及通道设置。CH5 Custom Failsafe仍为1500µs（0%），不要因更新固件而改变。接收机保持数字地接法。
2. 先断开电机，检查两路正反转及归位命令的PWM应为10kHz、60%，停止为0%。用示波器测对应IN PWM：周期约100µs，有效高电平约60µs、低电平约40µs；方向相反时切换到另一输出，非活动IN保持低电平。48V母线下理想平均约28.8V，PWM脉冲仍接近48V，实际平均电压随母线和负载变化。
3. 先保持行走、割刀动力断开，仅接推杆进行短程动作；记录方向、实际电压、电流、温升、速度与行程时间，并核对10kHz实机波形。原高度显示和档位按旧时间表估算，本轮未重新标定。
4. 升降归位10秒、草袋动作20秒、高度时间表、上升补偿0.8和草袋关闭检测屏蔽14秒保留。本版不新增500ns死区、堵转检测或限流。
5. 摇杆回中，沿用CH4回中→左拨→OK解锁。割刀启动仍需独立的新CH4操作和OK；验证CH5、急停和碰撞仍能撤销输出。
6. 有效i-BUS帧持续中断达到300ms时逻辑撤权锁定；恢复通信不自动解锁。测试需保持控制板供电；关闭发射机可能仍有接收机failsafe有效帧，不能等同于无帧看门狗试验。实际机械停车还包括调度、通信和制动时间。
7. 若草袋状态持续未知，检查接收机和回传，必要时在TELEMETRY中Discover new sensors后Stop discovery，不初始化模型、绑定或校准。

## 自行锁定后抓取

保持供电，不重新解锁、不拨CH5、不重启、不再次刷写。只读命令：

```bash
python3 read_remote_stop_diag.py \
  --elf control-chassis-actuator-10khz-60pct-ibus300ms.elf \
  --bin control-chassis-actuator-10khz-60pct-ibus300ms.bin \
  --gdb /usr/bin/gdb-multiarch \
  --output actuator10khz60pct-stop-01.json
```

必须显式指定本包ELF/BIN；脚本默认文件名仍属于旧包。工具暂停CPU核对Flash及冻结SRAM后恢复运行，不刷写、不复位。详见[ST-Link读取说明](ST-Link读取说明.md)。

## 回退本次更新前15kHz／40%／300ms

rollback-15khz-40pct保存本次更新前版本，包含原样BIN/HEX/ELF/MAP。仅在需要恢复此前镜像时使用；该底盘将恢复15kHz、40%和300ms，48V下理想平均约19.2V。保持动力断开，刷写后Verify：

```bash
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg \
  -c 'adapter speed 100' -c 'reset_config none' \
  -c 'program {rollback-15khz-40pct/control-chassis-actuator-15khz-40pct-ibus300ms.bin} 0x08000000 verify reset exit'
```

如需成对恢复原遥控器，在DFU中写回：

```bash
dfu-util -a 0 -s 0x08000000 -D rollback-15khz-40pct/fs-i6x-actuator15khz40pct-paired.bin
```

回退后诊断读取必须改用该目录底盘同名ELF/BIN。原配套0x36遥控器对两种PWM配置均可使用，不清除模型、绑定或校准。

## 定时器共享边界

当前生产割刀为FTESC CAN，不使用TIM2 PWM通道。若自行选择旧PWM割刀配置，TIM2 CH2与草袋共用周期，恢复后同为10kHz。本轮不切换割刀驱动，不改变CAN割刀转速，也不增加500ns防直通死区或限流。
