# 遥控首次撤权诊断

`g_app.remote_stop_diag`由100Hz Motion独占写入，不控制输出或授权。启动时记录RCC复位标志并清除硬件复位标志；复位后的记录有效性和事件计数归零。

每次手动运行许可恢复时重新布防，并保存时间、帧/超时/CH5序号及接收计数基线。首次从允许运行变为禁止时，记录仲裁原因、授权状态/原因、当前链路年龄和输入、高度目标、TIM3实际PWM、原始GPIO及接收诊断。此后禁止运行期间不覆盖，避免后续故障或调试暂停覆盖首次现场。

记录包含magic `0x52534431`、版本1、实际结构大小和发布序号。序号奇数表示写入未完成，偶数才允许读取；valid=0表示本次启动尚无已捕获撤权，不能据此排除复位。地址和字段偏移必须来自对应生产ELF的DWARF。

## 原因与计数

- `gate_reason`沿用SafetyOwnershipGateReason_t，可能因已设置软件锁而为software_lock；须同时查看`latch_reason`和输入。
- `latch_reason`：0无、1重新同步、2超时、3遥控停机、4控制权切换、5安全拒绝。
- `input_flags`位序定义见头文件：连接、新鲜、稳定、历史超时、当前超时停车、遥控锁存、运行许可、软件锁、硬件锁存、实际保护输入和保护使能。
- `rx`为事件时的累计计数；`rx_at_authorization`为本轮运行许可建立时的基线。CRC错误、无效映射通道、UART错误、过期队列、溢出和流重置分别计数；不能将开机旧错误认定为本次推杆干扰。计数饱和时零增量不能证明没有新错误。
- `last_uart_error`保留HAL错误码；F407中PE=1、NE=2、FE=4、ORE=8、DMA=16。原收流恢复行为未因诊断改变。

## 故障后读取

使用`tools/read_remote_stop_diag.py`及同一发布包的底盘ELF/BIN。需要OpenOCD、支持ARM和Python的GDB（优先gdb-multiarch）、arm-none-eabi-objcopy及ST-Link。脚本先本地核对ELF提取的BIN，再连接设备；不下载、不复位、不解锁。

仅在实际锁定后执行，期间不重新解锁或重启设备。脚本暂停CPU，核对Flash，连续读取两次冻结SRAM，再通过独立Tcl通道恢复CPU并确认running。读取失败、GDB退出或超时仍走恢复；若无法确认恢复，会明确报错。此前运行态SWD读回出现过错位，因此不依赖运行中多次非原子读取，也不使用暂停调试测量保护时延。2026-11-04起主程序有效i-BUS帧超时默认300ms，100ms保留为显式回退构建；读取时仍须匹配实际安装固件的ELF/BIN。

当前仍解锁、记录未提交、SRAM不一致、ELF/BIN或Flash不匹配时拒绝给出有效诊断。若推杆动作导致MCU重启，记录会无效，但复位标志和运行时间可提供线索；正常上电也可置BOR/POR，不能仅凭这些位断言掉压。故障捕获不替代接收机供电和SERVO信号测量。
