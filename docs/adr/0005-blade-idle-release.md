# 割刀停转后：先制动，再零电流释放

现场现象：割刀处于关闭状态，遥控器也显示关闭，刀盘升降时割刀偶尔抖一下或转一小段，随后自行停止。原先割刀关闭期间，底盘每 200ms 向 FTESC 发送一次 `0x18` ERPM=0，电调一直停留在零转速闭环中。FTESC 驱动的是无感电机，零转速附近转速几乎不可观测。升降推杆 H 桥（TIM3，48V 母线）启动或换向时会带来母线/地扰动和机械冲击，电调可能把它误判为转速，转速环随即短暂输出力矩，表现为抖刀。底盘软件在此期间没有下发任何非零 ERPM。

决定把割刀停转分为两段。无论零意图来自哪里（正常关刀、安全门拒绝、急停/碰撞/失联、非法输入），第一段都先继续发 `0x18` ERPM=0 制动 `BLADE_FTESC_STOP_BRAKE_MS`（默认 3000ms）。窗口结束后改发 `0x15 CAN_SET_CURRENT_GEAR`：电流为 0，挡位 0x00，DLC 5，不带 CRC。电调收到后停止驱动，电机自由滑行；该帧仍按 200ms 周期重发。窗口从“电机可能在转”之后的第一个零意图开始计时，即上电或任何被接纳的非零运行帧之后；重复零意图不会重新开始计时。上电时也先走制动窗口，因为 MCU 复位时割刀可能仍在惯性转动。

释放帧选用 `0x15`，而不是 `0x00`/`0x03` 等带 CRC 的电流帧。原因是 `0x15` 与已经实机验证的 `0x18` 帧结构完全相同（int32 + 挡位，无 CRC），不会引入 CRC 高低字节顺序的新风险；现有 `0x03` 实现的 CRC 字节顺序与手册不一致，而且没有生产调用点，本决定不动它。保留制动段而不是立刻释放，是为了维持正常关刀时的减速能力，不把停刀时间完全交给惯性滑行。

释放帧与 ERPM=0 一样属于停刀请求：走专用邮箱 2，必须等到 TXOK 才算完成，待完成期间拒绝非零请求。已有停刀待完成时，新到的释放帧不会替换它（保持原停刀的身份和年龄），因此最坏会推迟一个保活周期（≤200ms）才发出，这不影响安全。“已接纳释放帧”和“CAN 发送成功”都不等于电调已释放或刀盘已停止，三者分别验收。

`BLADE_FTESC_IDLE_RELEASE_ENABLED=0` 可在编译期恢复原来的“始终 ERPM=0 保持”，作为现场回退开关。如果实机确认 FTESC 收到 `0x15` 电流 0 后并不释放，就使用该开关回退，再改为排查 ESC Tool 中的转速环/无感参数。本决定只改动底盘与 FTESC 之间的 CAN 指令，遥控器、SENS 和 `EXP3_WIRE_VERSION`（0x36）均不变，与 ADR 0001～0004 不冲突。
