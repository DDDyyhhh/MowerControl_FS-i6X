# FS-i6X 开机授权协议 0x35 / E9 profile 3

以 SVN r105（v2 + BMS反馈仅诊断）为基线。正式 `MOWER_BLADE_OK_ENABLED=1` 双端使用0x35；历史实验配置继续0x31。旧0x33、已撤回的0x34以及两字节E9均不能授权。该协议是串行链路差错及重放防护，不是密码学认证。

## 周期状态

SENS地址10、类型E9保持不变，类型响应声明4字节（`E9 04`）；测量响应8字节，四字节值按小端排列。接收机须转发AFHDS2A AC长度4记录；AA和AC长度2仅视为旧格式，不建立运行/授权心跳。地址1..9及11..15的协议保留，E1空闲槽仍仅为电池诊断，不参与授权。

低16位保留原profile2运行、锁定、急停/碰撞原因和模64心跳。高16位如下：

| 高半字位 | 内容 |
| --- | --- |
| 0..11 | 底盘令牌，1..4095；0仅用于尚无请求的基线 |
| 12 | 上下文：1=UNLK解锁，0=BLAD割刀 |
| 13..15 | 阶段，见下表 |

| 阶段 | 意义 |
| --- | --- |
| 0 | 初始化、绑定或链路尚未稳定 |
| 1 | 实际急停、碰撞或倾斜输入阻断 |
| 2 | 行走摇杆未连续回中200ms（仅解锁） |
| 3 | 需要新的CH4回中→左拨操作，或原令牌已失效 |
| 4 | 底盘已观察到满足条件的CH4回中 |
| 5 | 实际状态机已建立请求，等待该令牌的明确OK |
| 6 | 有效低电禁止割刀 |
| 7 | 当前不是遥控控制模式 |

Motion在同一次源快照中生成32位值，以对齐的32位存储原子发布；SENS ISR只读一次，不等待任务写者。第一次接收只建立心跳基线，前进1..31才建立/更新有效性，1000ms未前进即失效。重复心跳不更新授权阶段，不延长新鲜度；旧运行状态的限制合并规则保留。新绑定清空接收缓存。

## 操作生命周期

解锁环境检查与实际Confirm共用条件：链路新鲜且稳定、CH5有效、遥控模式、实际安全输入已释放、CH1/CH2连续回中200ms。软件锁定和已释放安全原因的历史锁存不是准备条件，合法解锁负责清除它们。BMS缺失、超时、无效值不参与这些检查。割刀准备仍使用原有独立割刀状态机、安全门和有效低电检查，不额外要求行走摇杆回中。

底盘只有从阶段4进入实际确认请求时才分配新令牌，记录实际请求序号、上下文和分配时间。令牌在当前会话内统一递增，不从射频CH4帧独立累计。解锁与割刀不能共用一次OK；当前上下文切换会使旧准备失效。

遥控器只有在本地CH4回中且收到阶段4后，才记录底盘基线令牌。随后新左拨等待大于基线的阶段5令牌，再弹确认。等待中的短暂回传缺口和CH4过渡帧不清除这条物理操作；1000ms未取得新令牌则丢弃操作。过早OK只丢弃该次按键，不排队，也不把正常的等待永久变成“请回中”。中断达到新鲜度期限、明确安全/控制权阻断时须重新操作。

确认的controller/hmi、上下文、target、令牌和action/request发送后固定，仍通过完整消息CRC及端点去重。Motion在实际执行前校验并单次消费令牌，再检查真实安全条件；割刀适配器再次检查实际请求、CH4位置及安全门。相同请求的重复报文只返回完成缓存。过期或旧代次的Cancel只排空原事务，不能取消新请求。

未消费令牌在分配后10000ms失效；回中、明确阻断、拒绝、会话切换均使本次意图失效。保持左拨不重新发令牌。4095是最后一个可用值，下一次分配前撤权、变更非零controller身份并自动重握手，不截断复用。Motion只投递重绑定请求；Comm负责修改链路/会话发送状态，随后通过无消息身份的取消事件撤销后端和割刀授权。

确认/取消从实际发送开始满10000ms仍无匹配完成回执，遥控器变更HMI身份、清空旧事务并重新握手。重绑定不是解锁，必须重新回中、左拨、按新的OK。只有匹配Accepted和新鲜底盘许可状态都成立才关闭成功等待；2秒不再静默隐藏失败。若Accepted已到但许可运行状态始终未到，发送满10000ms也按超时撤权重握手；完整确认成功后，后续反馈过期只更新首页未知状态，不重新弹出等待框。初始化与阶段提示仅在CH4左拨尝试时显示，CH4回中时保留离线维护菜单入口。新会话、拒绝和超时后的旧OK不自动执行。成功解锁仍需新控制帧才有行走输出。

## 定位记录

底盘调试器读取 `g_exp3_hil.controller/hmi/authority/token/token_at/token_request/intent_reason`；读取模块诊断使用 `exp3_board_read_pwm_diag`（任务上下文）。`g_exp3_pwm_diag`保存解锁动作/请求/确认令牌、底盘令牌、实际请求序号、CH1/CH2/CH4原始值、授权阶段、最终结果及确认/拒绝计数。拒绝原因：0成功；1会话/目标；2令牌/上下文；3已消费/过期；4实际授权条件；5控制模式。割刀仍保留原适配器拒绝原因。

现场记录设备和双端BIN哈希、上下电顺序、CH4/摇杆/OK时刻、阶段/令牌变化和最终回执，区分“准备未建立”“令牌被拒绝”和“回执丢失”。软硬件验收分别记录，主机模型不代替接收机四字节E9和动力实测。
