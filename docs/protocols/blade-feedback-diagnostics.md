# 割刀反馈诊断规则（2026-10-22）

FS-i6X故障字bit8（0x0100）为实际割刀转速反馈过期，bit9（0x0200）为FTESC实时包CRC错误，编号与现有SENS格式保持不变。首页仍由任一非零故障显示“报错”。

实际转速反馈未完成硬件验证时，FLIPSKY_REALTIME_FEEDBACK_VALIDATED=0，RPM按既有接口返回0（不可当作实测停转），不再仅因该门未启用设置bit8。硬件验证启用后，必须有CRC通过的0x00009A0C样本且年龄不超过500ms；500ms有效，501ms过期，其他实时帧不能续期转速样本。未收到有效样本或freshness窗口无效也置bit8。

收到ID=154、DLC=8且命令为0x0B/0x0C/0x0D的匹配包后，核对前6字节的CRC。校验失败置bit9并累计计数，不更新有效样本及时间；下一帧匹配且CRC正确的实时反馈清除活动标志。无关ID、长度和命令不清除。该错误不因实际RPM尚未启用而被隐藏。

CRC沿用仓库FTESC V1.4参考代码的0xFFFF初值、反射0xA001算法，实时包按参考接收示例data[6]高、data[7]低读取。生产使用正确的四位表，测试使用独立逐位算法与参考全表冻结值：ASCII 123456789 -> 0x4B37；00 00 3E 80 01 F4 -> 0x0C0C。旧测试复制了错误表，已更换独立参照。共享CRC调用点的校验值同时修正，各既有指令字节位置保留；当前0x18 ERPM控制不带CRC，不受算法数值变化影响。

这两项诊断不新增停车联锁、不改变急停或授权。CRC正确只能证明字节校验一致，不能证明ERPM字段、方向、极对数、机械转速或CAN失联停车已经实机验收；Ticket09保持待实机验证。
