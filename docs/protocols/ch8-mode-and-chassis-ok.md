# CH8 控制源与独立底盘 OK 确认

适用：FlySky 生产配置 `MOWER_BLADE_OK_ENABLED=1` / 遥控器 `PCBI6X_MOWER_BLADE_OK`。确认协议版本为 `0x33`，两端配套更新。A28/E34 与独立 EXP3 台架配置保持原契约。

## 控制源与运行许可

CH8 只选择控制源：1000±120µs 和 1500±120µs 为遥控，2000±120µs 为 API。连续三个新有效 SERVO 帧确认选择；重复读取快照不计数。软件初始选择遥控，开机锁定。无效位置或接收失联停止输出并撤销解锁；恢复后必须再次 OK。

“底盘已解锁”是独立于控制源的运行许可。正常切换保留该许可，但停止行走、割刀、升降、草袋及巡航，清除上一控制源的动作缓存与确认事务。新控制源只能使用切换后的新指令。升降撤销许可时同时取消旧目标与归位状态，周期任务和撤销操作的 PWM 写入互斥，重新许可本身不能恢复旧动作。API 尚未完成启动时，行走摇杆不能驱动车辆。

`Ctrl_Mode` / CAN 0x507 Byte4 仍为 0、1、2：遥控或 API 尚未挂载、API 待机、API 运行。CH8 选择与该状态分别回传；CH8 已选 API 而尚未挂载时，CAN 状态仍为 0，但不授予遥控控制权。

API 必须在切换并解锁后重新发送 `1 → 2`；旧待机帧不能满足新一轮启动。CAN 接收只发布快照，运动任务统一消费。遥控选择时 API 请求无效；生产配置的 Byte7 `0xAA` 不能解除 OK 锁。未知状态值、错误 ID、DLC 不等于 8 或超过 500ms 的缓存帧不执行。API 运行心跳满 500ms、行走摇杆偏离回中范围、CH5 停机、当前有效安全输入触发，均停车并重新锁定。API 的 `ctrl_mode=0` 在已挂载时也撤销许可；恢复需要新 OK 和新启动流程。

## 底盘解锁

满足以下条件才发布可确认状态：已绑定当前协议会话；SERVO 链路稳定有效；CH8 选择有效；CH5 位于运行使能；行走摇杆在 1500±50µs 连续回中 200ms；CH4 位于 1500±100µs；当前急停、碰撞、倾斜输入允许恢复。现有物理输入的编译期开关与阈值保持原配置。

底盘 OK 只解除已经消退的锁存，不越过仍有效的安全输入。接受后继续等待新的遥控帧；安全仲裁门也继续阻止切换前或解锁前的命令。解锁条件消失会废弃本轮请求，条件恢复后重新生成可确认请求。

底盘锁定期间不处理割刀启动 OK。底盘解锁后，操作员仍需重新完成 CH4 回中到启动的操作，并单独确认割刀。首页菜单的 OK、长按释放和后台轮询不产生解锁确认。

## 确认消息

沿用现有 CH11/CH12 上行、SENS 地址 9 下行、36 字节消息与 CRC32。共享定义：`experiments/ticket03/mower_control_contract.h`。

| 字段 | 底盘解锁 |
|---|---|
| context | `0x43484153`（CHAS）；割刀仍为 `0x424C4144`（BLAD） |
| target | 1 |
| request / action | 同一个非零动作序号；底盘、割刀共用当前会话的全局递增序号 |
| generation | 当前底盘发布的非零 16 位解锁代次，装入既有 32 位字段 |
| kind | 既有 Confirm / Cancel / Query / Result |

Confirm 必须匹配双方会话、上下文、目标和代次，并由运动任务在当前条件下接受后才能返回 Accepted。底盘与割刀分别去重与分派，共用串行传输队列。重复报文可回放缓存回执，不能重复授权。未知上下文不能返回成功。

重新锁定、有效模式变化、会话变化会推进解锁代次。16 位代次耗尽时先停止并发起一次新会话握手，握手完成后从 1 重新计数，不能在同一会话内复用。当前代次的 Cancel 撤销本轮许可；过时代次的 Cancel 只确认取消，不影响后续授权。条件或代次变化时，遥控器排空旧事务后再显示新提示。

快速回执仍为 17 个传输字。压缩字节 12 的 bit7 在 `0x33` 中标记 CHAS；其余状态和命令位保留。解码先还原上下文，再校验原完整消息 CRC32。动作或代次超出压缩范围时沿用完整回执传输。旧版本不能通过 `0x33` 消息校验。

## SENS 回传

新增地址均为两字节、小端值；发现、类型和测量校验沿用现有 SENS。地址 1～11 的用途保持原样。

| 地址 / 类型 | 值 |
|---|---|
| 12 / `0xE4` | 当前非零解锁代次；0 表示不可用 |
| 13 / `0xE5` | 下表的控制状态与运动任务心跳 |

| 地址 13 位 | 含义 |
|---|---|
| bit0 | 底盘已解锁，独立于当前控制源和 API 待机状态 |
| bit1 | 当前可接受底盘 OK；与 bit0 互斥 |
| bit2 | CH8 已选择 API |
| bit3～4 | 当前 `Ctrl_Mode`，0～2 |
| bit5 | 当前会话、稳定链路和模式选择有效 |
| bit6～15 | `floor(now_ms / 100) & 0x3FF`，由运动任务发布 |

遥控器在已通过 RF CRC 和绑定 ID 校验的 AA/AC 中，仅接收准确类型、地址和两字节宽度。首次状态只建立心跳基线，模差 1～511 的前向推进才确认有效；相同或倒序心跳不续期。相同心跳只允许收紧锁定/可确认状态，不能恢复已解锁状态。无效状态立即清除有效性。

状态心跳最后推进、代次最后接收任一满 1000ms，即禁止 OK 并显示模式未知。重绑定清除两个缓存，恢复需要重新建立基线并看到心跳推进。时间和心跳回绕使用无符号差值；底盘时间计数重置或 32 位计时回绕引起心跳跳变时，最多经历一次超时与基线重建。SENS 反馈只驱动显示与请求身份，最终授权始终由底盘运动任务决定。

## 实机验收边界

Host harness 验证状态机、两类事务、AA/AC、回放和超时；两端 ARM 构建不能替代实机验收。接收机必须实际发现并持续轮询地址 12、13；测量模式切换停车时间、OK 往返时间、失联及恢复表现。按发布目录的步骤在动力输出隔离条件下完成验证，再进行受控运动测试。
