# CH8 控制源与授权契约 v37

适用正式 FlySky `MOWER_BLADE_OK` 双端固件，`EXP3_WIRE_VERSION=0x37`。在 [v36 快速确认](startup-authorization-v36.md) 与 [v35 授权条件](startup-authorization-v35.md) 上增加本契约；冲突处以本文为准。v35/v36 文档保留作历史记录。设计理由见 [ADR 0006](../adr/0006-ch8-control-source.md)。

## CH8 与控制源

| 原始 CH8 脉宽（µs） | 含义 |
| --- | --- |
| 900..1120（约1000） | 遥控 |
| 1380..1620（约1500） | 遥控 |
| 1880..2100（约2000） | API 允许档 |
| 其它值 | 未知，停止输出，等待重新确认 |

Motion 100Hz 消费 3 个序号不同的有效帧后确认档位；同一帧被重复读取不累计。Comm 记录每次解码档位变化，即使中间帧在 Motion 读取前被覆盖也会停止输出、作废旧命令。1000 与1500 同属遥控，二者之间不构成控制源切换。有效帧中的非法 CH8 直接发布为未知；不得继续沿用上一次许可直至链路超时。

CH8 只选择控制源，与 `cfg_op_mode` 的割草行为模式和底盘授权分开。只有遥控档允许首次/故障解锁：CH4 回中 → 左拨 → OK；仍须 CH5 许可、CH1/2 回中及其余安全条件。CH8 不解锁，普通切换不消耗已有底盘授权，未完成的确认请求会取消。遥控割刀启动仍须独立 CH4/OK。

## 交接与摇杆接管

每次有效切换先清空行走速度、巡航、割刀输出/确认、高度目标/归位和草袋请求，提交四类执行器的停止。控制源改变不会继承上一来源的非零意图。遥控接手后 CH1/2 必须在 1450..1550µs 连续 200ms，方可接受新动作；高度先建立旋钮基线，随后旋钮变化才执行；草袋也先建立 CH6 基线。不得自动恢复旧高度、旧草袋动作或旧割刀 OK。

API 允许档下，只要 CH1 或 CH2 原始值离开 1450..1550µs，即停止 API 并锁定为“接管”。即使回中或上位机不断重发 1/2，也不得重新进入 API。须 CH8 稳定回遥控，再稳定拨 API，再发送本次之后的新 1 → 2。摇杆接管本身保留底盘授权，模式值4表示接管，不额外制造安全故障位；若同时发生安全故障，故障仍照常锁存并优先显示。

## CAN API

标准数据帧 `0x005`、DLC=8，建议 50ms 周期；字节布局见 [RK3588 手册](../../control_chassis/RK3588_CAN协议手册.md)。非法模式或长度不更新新鲜度。CANRx 仅发布快照，Motion 按接收时间与顺序决定执行，排队旧帧不刷新许可。Byte7 在正式配置中忽略，`0xAA` 不清锁。

| Byte0 | CH8 允许且底盘已授权时的含义 |
| --- | --- |
| 0 | 停止并回 API 待机，废弃旧握手；不改变 CH8 选择，不撤销有效底盘授权 |
| 1 | API 待机，停止全部执行器并记录本次待机；不清除摇杆接管锁 |
| 2 | 只有新鲜 1 → 2 后才进入 API 运行；持续收到新运行帧才可输出 |

握手的待机1必须晚于本次切换/授权恢复的时间和序号屏障，晚于最后一次0，且待机1与当前运行2都未满500ms。相同毫秒的待机帧保守拒绝，发送下一帧即可。待机及运行即使被快照覆盖，其停止/退出事件也保留。进入运行的那一周期保持停止，后续新鲜2通过安全门后执行；因此上位机应持续周期发送，不能仅发送两个单次帧。

API 覆盖行走（vx、omega）、割刀档位（0..3）、高度（1..5）和草袋目标（开/关）。API 运行时不要求遥控割刀 OK，也不使用遥控器的速度旋钮作为 API 速度；所有输出仍经过安全门，草袋须连接。`0x507` 布局不变，Byte4为0遥控/1API待机/2API运行，速度字段为命令回显；它不构成执行确认或机械结果。

## 安全失效

CH5 禁止、物理急停/碰撞/倾斜、系统锁、电池停机和遥控失联继续阻断全部输出。i-BUS 超时以实际接收年龄判断，正式默认300ms，构建回退100ms仍受支持；Comm 停顿不影响 Motion 的独立检查。API 运行帧年龄达到500ms时停车、撤销授权并锁住API；恢复须回遥控档重新解锁。CH8 未知只停止和清命令，已有安全授权不因单独的未知档位撤销。

停止为软件输出和 CAN 调度请求，不等于机械已经停止。FTESC 沿用现有先零转速制动、再释放的策略；当前 `blade_motor_config.h` 默认 `BLADE_FTESC_RELEASE_USES_DUTY=1`（0x02零占空比），也保留 [ADR 0005](../adr/0005-blade-idle-release.md) 的0x15零电流回退配置，停刀 TXOK、刀盘停止和推杆停止分别实测。

## 双端协议与显示

规范消息 Byte1 和自动握手 CRC8 版本盐从0x36改为0x37；CRC8 初值为 `0x5a XOR role XOR 0x37`。完整36字节消息、9字快速上行、E9/profile3与快速完成回执布局不变，CRC32使用新的规范版本。v35/v36不得建立v37授权会话，两端必须配套刷写。

SENS 地址6、类型0x16、16bit 工作模式扩展为：

| 值 | 首页显示 | 含义 |
| --- | --- | --- |
| 0 | -- | 控制源未知/未稳定 |
| 1 | 遥控 | 遥控选择 |
| 2 | API待机 | 等待本次新握手或已停止 |
| 3 | API运行 | API 状态机运行，动力仍取决于安全门 |
| 4 | 接管 | 摇杆/超时接管锁有效 |

运行许可（原SENS 0x15及E9相应位）来自当前实际所有者的安全门许可，而非只报告遥控许可。首页在API状态显示实际车速和“草袋API”，避免把本地CH10/CH6设置当作API命令回显；高度继续用底盘估计反馈。无遥测或模式非法显示未知。界面不授予权限。

## 验证边界

host 验证编译生产状态机、CAN解析、Motion交接和执行器调用边界，覆盖时间/序号回绕、快速往返、失联/超时、积压帧、故障和独立OK。双端ARM构建及遥控器实际ELF传感读取仿真属于软件验证。首次开机、API四类执行器、所有停止原因和反复接管还须配套硬件验收；本次未刷写设备。
