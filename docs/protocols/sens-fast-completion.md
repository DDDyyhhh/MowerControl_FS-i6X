# 割刀与解锁快速完成回执（0x35 配套版）

新增 SENS 地址 13、14、15，类型 E6、E7、E8，测量值均为 4 字节。发现响应仍为 4 字节，类型响应仍为 6 字节并声明长度 4，测量响应为 8 字节（含原 i-BUS 校验和）。地址 1～12 的含义和帧长不变。接收机须转发 AFHDS2A AC 的四字节传感值；AA 两字节值不用于本回执。

每个测量值的低字节是非零发布序号，高三个字节依次承载九字节结果的第 0～2、3～5、6～8 字节。序号从 1～255 循环，0 表示尚无完成结果；同一次发布的三片必须使用同一序号。接收端允许分片乱序、忽略重复片，组装窗为 1000ms，拒绝窗口内倒退的序号。绑定变化和新命令提交清空组装状态。

| 结果偏移 | 内容 |
| --- | --- |
| 0～1 | action，LE16；request 固定还原为 action |
| 2～3 | generation，LE16 |
| 4 | bit0～1 command，bit2～4 status，bit5 为 UNLK（0 为 BLAD），bit6～7 必须为 0 |
| 5～8 | 原始 36 字节 RESULT 的 CRC32，LE32 |

还原时采用当前 controller/hmi 会话、协议版本 0x35、RESULT/sender=2、target=1，执行现有 `exp3_decode` 的完整消息校验。随后进入 `exp3_hil_apply_result`，逐项匹配 pending 的会话、request/action、上下文、代次、目标和命令。CRC 用于差错检测，不是身份认证。普通 E5 运行状态不能结束通信事务，也不能授权启动。

只有 Motion 完成状态机处理后，才能发布 ACCEPTED 或 CANCELLED。拒绝结果沿用现有状态码；非 CANCELLED 不能清除取消忙状态。接收端只在当前命令已完整发送后处理快速回执，不截断命令帧，不缓存忙碌时按下的 OK。

底盘将 Motion 执行槽与慢回执发送槽分开。执行槽完成即释放；正在发送的 E1 帧保持完整，尚未发送的旧结果合并为最新结果。重复请求只返回缓存完成结果，旧 Confirm 不覆盖同 action 的 Cancel，旧 action 不覆盖更新结果。会话重绑清空两种回执状态。

原 E1 完整回执继续发送。无新传感器、分片缺失、错误或 action/generation 超过 65535 时，沿用完整回执和原有超时/取消重试行为；没有快速回执时不承诺新的性能指标。

电池诊断与快速回执共存：13～15/E6～E8保持本协议独占。地址9/E1仅在原事务字为0时使用0x4000/0x6000前缀发送最低单体和原因，接收端先分流诊断，再交给既有会话/结果解析器；不改动任何活动帧或完成分片。格式、心跳和失效规则见[电池接口说明](../../control_chassis/docs/battery_monitor.md)。低电警告/禁刀仍在E0 bit11/12中传递，不等待空闲诊断。

界面将“通信完成”与“观察到输出状态变化”分开：本次命令之后 E5 心跳前进且输出开启时收起启动等待；停止操作后观察到心跳前进且输出关闭时收起取消等待。显示收敛按本次操作锁存，反馈暂时未知不重新弹旧框。再次启动仍需新 CH4 回中、左拨及有效 OK。

验证入口：`ASAN_OPTIONS=detect_leaks=0 python3 tools/test_fast_completion.py`、`python3 tools/test_blade_ok_ui.py`，均纳入正式 `tools/build_blade_ok.sh`。

主机模型采用 15 槽、每槽 10ms、150ms 周期、5ms RF 延迟、20ms 上行字保持、20ms Comm 和 10ms Motion。覆盖 150 相位和额外连续 100 轮；PWM/FTESC 均测得解锁完成最坏 479ms，割刀启停完成最坏 476ms。界面下一次轮询再增加至多 10ms，模型上界为 486ms。模型不证明接收机实际四字节转发、实机屏幕延迟或机械停止时间。
